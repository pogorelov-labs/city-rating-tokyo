Derived file
------------
medicine-jnto.json — merged array, one object per institution:
  {pref, name, name_ja, category, lat, lon, address, phone}
  - pref      English prefecture name (from the cb-area option label; the API's
              own `pref` field matched the requested prefecture for all 2721 rows)
  - name      `medical_institution` from search-lang=eng
  - name_ja   `medical_institution` from search-lang=jpn
  - category  derived, not from the API (the API has no type field):
                hospital — name (ja or en) matches /病院|[Hh]ospital/
                dental   — else name or any d01..d16 department matches /歯|齿|[Oo]ral|[Dd]ental/
                clinic   — everything else
              (Precedence hospital > dental > clinic. Counts: hospital 937,
               dental 674, clinic 1110. This is an inference for internal
               ranking purposes; the source itself does not classify types.)
  - lat/lon   float(latitude/longitude) from the API; all 2721 rows parsed,
              all inside Japan bounds (20–46.5 N, 122–154.5 E)
  - address   `street_address` (English page: includes postal code; 1 row of
              2721 has an empty address in the source — kept as "")
  - phone     `phone_number`
Known source artifact (not a pipeline bug): 276/2721 English name/address
fields are stored in the API without spaces (e.g. "IncorporatedMedicalInstitutionYushinkaiHakodateShintoshiHospital",
"331-1Ishikawacho,Hakodate..."), mostly Hokkaido/Tohoku entries. Copied as-is;
the Japanese name_ja field is unaffected.
eng and jpn rows were merged by index; per-prefecture the (phone, postal, lat)
triple matched for all 2721 index pairs (0 mismatches).
Not carried over from the API (available in raw/): reception_time, websites,
