# Integration review — research corpus → DB & UI (map, cards, guide) (2026-11-08)

A detailed, code-grounded review of what it takes to surface the research
program's findings in the app: data files ("database"), map cards, the area
guide, and the evidence layer. Companion to the E-1 draft spec — this doc
grounds it in the **actual components** and answers "new fields or something?"
field by field. Nothing here is implemented; everything is gated on A-1
except where noted.

## 0. What the app already has (the discovery that shapes everything)

The UI **already implements the hard patterns** the research needs:

| Existing | Where | Reuse for research |
|---|---|---|
| Per-category **evidence rows** (expandable: confidence tag + sources list) | `AreaGuide.tsx` ~L157–174 (`evidence-${key}` rows, `area.sources[key]`) | claim-level evidence drawer follows the same pattern one level deeper |
| **Confidence taxonomy** `strong/moderate/estimate/editorial/unknown` | `messages/*/common.json → areaGuide.evidence` | maps 1:1 onto claim statuses (`corroborated→strong`, `proposed→estimate-like w/ attribution`, `conflicted→never in copy`, `researcher_inference→editorial`) |
| **Score-basis disclosure** ("Score basis & data coverage") | `areaGuide.score.basis` + `<details class=disclosure>` | E-3's green-buffer/transport-mechanism/rent-label disclosures **extend this existing panel** — no new placement needed |
| **Rent provenance enum** (`stationAverage/districtBlend/estimate/…`) + proxy-confidence copy | `AreaGuideData.rent.provenance`, `bangkok.rent.proxyConfidence` | B-5's "keep blend/override/median visible" is already satisfied structurally; only label wording may need a pass |
| **Server-side adapter** keeping heavy data out of card payloads | `area-guide-data.ts` (imports geometry/images at build, exports slim `AreaGuideData`) | the editorial exporter plugs in here — same architecture as E-1 proposes |
| **Short-copy bridge** `area-guide-copy.json` (6 Bangkok keys, en/ja/ru) with fallback chain (copy → district atmosphere → i18n template) | `area-guide-data.ts` L143 | the preview text flows through the **same fallback chain**; existing keys are never overwritten (E-1 §8) |

Conclusion: **integration is incremental, not architectural.** No new data
pipeline pattern, no new UI paradigm — one exporter, one adapter field, two
new components, a handful of message keys.

## 1. Data layer ("database") — two new build artifacts

### 1a. `app/src/data/bangkok/editorial-index.json` (build-imported, budget ≤ ~120 KB gz)

Generated by `scripts/bangkok/export-editorial.mjs` (E-1) from the 55
researched bundles + 137 tier-C identities. **One record per entity**:

```jsonc
{
  "_meta": {
    "generated": "2026-11-08T…", "schema_version": "1.1",
    "rule_version": "<audit-rules git sha>",          // WS-H #10: counts are rule-relative
    "input_digests": {"batch_dirs": ["…"], "registry": "<sha>"}
  },
  "entities": {
    "st.sala-daeng": {
      "tier": "A",
      "review": {"status": "approved", "signatory": "none|human|agent",
                 "reviewed_at": "…", "reviewer": "…"},
      "copy_eligible": false,                        // E-5 human-sign-off key: false until A-1 signs
      "as_of": "2026-11-08",
      "window": ["2024-11", "2026-11"],              // E-8 observation window stamp
      "preview": {"en": "…"},                        // evidence-bar-checked (corroborated-only basis)
      "stats": {"sources": 23, "body_read": 20, "claims": 18, "families": 16,
                "claims": {"corroborated": 7, "proposed": 11, "conflicted": 0}},
      "disclosures": ["green_buffer_1km", "transport_piers_buses", "rent_premium_blend"],
      "recheck_due": "2026-12-31",                   // min(temporal_scope.recheck_by) or null
      "chunk": "/data/bangkok/editorial/st.sala-daeng.json"
    },
    "st.bearing": { "tier": "C", "card": "data_only", "copy_eligible": false, … }
  }
}
```

**New fields vs today's data — the direct answer to "new fields or something?":**
`tier`, `review.signatory`, `copy_eligible`, `as_of`, `window`, `preview`,
`stats`, `disclosures`, `recheck_due`, `chunk`. The card/guide read **only
these**; everything heavier stays in the chunk.

### 1b. `app/public/data/bangkok/editorial/<key>.json` (on-demand chunks, ~55 files)

Fetched when the user opens a guide. Structure (all text plain, G20-swept at
export):

  "guide": {
    "lead": {"en": "…"},
    "sections": {
      "strengths":  [{"en": "…", "claims": ["sala-daeng-c01"]}],
      "tradeoffs":  […], "day_night": […], "variation": […], "fit": […],
      "uncertainties": ["…"]
    }
  },
  "claims": [{
    "id": "sala-daeng-c08", "text": "…", "kind": "researcher_inference",
    "status": "proposed", "topics": ["rent"],
    "temporal": {"event_date": null, "observed": "2025H2", "recheck": null},

    "limitations": ["…"], "conflicts_with": []
  }],
  "sources": [{
    "id": "src_…", "url": "https://…",

Claims whose status/bar forbids copy never appear in `guide` sections — the
exporter drops them there and they live only in `claims` (disclosure layer).

### 1c. What does NOT change

`stations.json` / `districts.json` / ratings / geometry / rent references /
`area-guide-copy.json` — untouched (handoff boundary; the six existing
Bangkok copy keys migrate via the exporter's collision manifest, E-1 §8).

## 2. Map UI (`DistrictMap.tsx`) — minimal changes

The map renders score-colored areas + labels; it needs **no rating or
geometry changes**. Changes:

1. **Guide-available dot** (optional, phase 2): a small marker on pins whose
   entity has `copy_eligible: true` — reads one boolean from the index.
2. Nothing else. Map payloads must stay slim (the adapter's own docstring
   says so); no editorial text enters map bundles.

## 3. Card UI (`AreaCardMeta` / `MobileStationCard` / `CompactAreaCard`)

Cards today show name + score (+camera icon). Changes, all index-driven:

| Change | Field | Tier behavior |
|---|---|---|
| **Editorial preview line** (1 sentence, secondary text under the score) | `preview.en` (locale-keyed, EN fallback) | researched units only; **absent for tier C** |
| **Data-only label** (E-6) | `card: "data_only"` | tier C renders "Scores only — editorial guide pending" instead of a preview |
| **Copy-eligibility behavior** | `copy_eligible` | `false` → no preview/guide link renders at all (agent-reviewed-only bundles show score+facts until A-1 signs) |
| **Freshness chip** (existing `data_date` pattern) | `as_of` | "Editorial as of 2026-11" beside the score, same treatment as the existing date chip |
| **Guide link** | `chunk` | "Read guide →" only when `copy_eligible` |

E-6's anti-laundering test: a fixture tier-C entity must render **no**
narrative fields — exporter + component test both.

## 4. Guide panel (`AreaGuide.tsx`) — the main new surface

1. **New `EditorialGuide` component** (lazy-loads the chunk on expand):
   renders lead + the five sections + uncertainties, in the handoff's section
   order. Register/length normalization (E-8) already applied at export time
   — the component stays dumb.
2. **Claim provenance inline**: each item carries `claims`; hovering/tapping
   a claim ref opens the **evidence drawer** (below). Claim text never
   inlines into prose.
3. **Evidence drawer** (new `EvidenceDrawer` component, same disclosure
   pattern as the existing evidence rows): lists the claims the visible
   guide cites — status chip (reusing the existing confidence vocabulary),
   temporal fields **with event dates rendered as dates** ("demolished
   2025-01", never "recently" — E-8), evidence locator + paraphrase per
   source, limitations, `conflicts_with` cross-links, sources resolved
   through the **B-11 attribution registry** (one attribution per URL).
4. **Disclosures (E-3) go into the existing score-basis panel** — one tap
   from the score, per the A4 amendment: buffer-basis line (green), transport
   mechanism line, rent-label line (mostly exists via provenance), plus the
   corpus-skew line (`skew_note`).

## 5. i18n

- **Guide copy** (preview/lead/sections): EN until WS-F; locale keys with EN
  fallback in the index (DEC-5 default: EN-only, flagged).
- **UI chrome** (~10 new keys × en/ja/ru — this part is NOT gated on A-1
  since it's generic UI text, but ships with the feature flag):
  `editorial.guide`, `editorial.readGuide`, `editorial.dataOnly`,
  `editorial.asOf`, `editorial.evidence`, `editorial.claimStatus.*`
  (reusing existing confidence words where possible),
  `editorial.skewNote`, `editorial.pendingSignoff`.
- Fallback rule: locale key missing → EN → hide (never machine-translate).

## 6b. Amendments (fourth review, same day)

1. **Entity precedence (the miss):** 9 upgraded entities have two researched
   bundles (superseded tier-B + tier-A). The exporter takes the highest tier
   per entity (see E-1 §2 amendment); without this rule every aggregation
   (recheck registry, B-11, evidence drawer) would double-count. The recheck
   registry and B-11 registry were already regenerated under the rule
   (603 items; 666 URLs).
2. **`recheck_due` must render**, not just exist: when `recheck_due` ≤ now,
   the card/guide shows a "facts due recheck" chip (existing date-chip
   pattern) — added to the §3 card table.
3. **`data_date` vs `as_of`:** the app's `data_date` (snapshot build, 2026-10)
   and the editorial `as_of` (research observation, 2026-11) are different
   clocks; the UI must label them separately ("scores as of" / "editorial as
   of") — conflating them would imply scores moved when only research moved.
4. **CI coupling:** the exporter reads `research/bangkok/editorial/…` at app
   build time — same repo, but CI must not break when research artifacts are
   mid-write: the exporter is deterministic + refuses partial inputs
   (digest-verified manifest), and the flag keeps the app buildable even if
   the exporter is skipped (empty index = pre-research UI).

## 7. Answers to "are there changes needed?" — the short list

- **DB**: two new generated artifacts (index + chunks); exporter step; zero
  changes to existing data files.
- **Map UI**: essentially none (optional availability dot).
- **Card UI**: preview line + data-only label + freshness chip + eligibility
  gating — all driven by the index.
- **Guide UI**: one new component + one drawer; disclosures extend the
  existing score-basis panel; claim refs resolve via the B-11 registry.
- **i18n**: ~10 chrome keys; guide copy stays EN until WS-F.
- **No changes**: ratings, scoring, filters, geometry, rents, existing copy
  keys, bundle size discipline (corpus never enters the map bundle).
