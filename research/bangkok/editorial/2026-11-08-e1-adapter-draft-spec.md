# E-1 (DRAFT) — Bangkok editorial adapter design spec (2026-11-08)

**Status: DRAFT for review — nothing implemented; gated on A-1 human sign-off
(G10) and the owner decisions already recorded at their defaults (DEC-5/6/8/10).
This document is the reviewable design the plan's E-2 implementation would
follow.**

## 1. Scope and build-step location (DEC-10 default: adopted)

- A **`scripts/bangkok/export-editorial.mjs` build step** (runs in the app's
  existing build pipeline) reads `research/bangkok/editorial/batches/*/profiles/*.json`
  and emits a **localized preview index** into the map bundle:
  `app/src/data/bangkok/editorial-index.json` (locale keys with EN fallback
  until WS-F; bundle-size delta budgeted ≤ ~120 KB gzipped — previews only).
- **Full guide narrative + evidence disclosure load on demand** from
  per-entity JSON chunks fetched at runtime (not in the map bundle) —
  `app/public/data/bangkok/editorial/<key>.json`, generated by the same step.
- The raw research corpus (sources, search logs, batch raw/) stays **out of
  the app tree entirely** (E-4 hard rule); only derived, filtered artifacts ship.

## 2. Input contract

- Inputs: the researched bundles at `ready_for_review`/`approved` + tier-C identities
  from the current app snapshot. **Precedence rule (fourth review):** 9 entities
  carry both a tier-B (batch 4, superseded) and tier-A (batch 5) bundle — the
  exporter takes the **highest tier** per entity and records the superseded
  batch as provenance (`superseded_by` in the index).
- `schema_version 1.0` only; the exporter refuses unknown versions (migration
  policy: additive — bump + migration notes in the exporter, never in-place
  rewrites of research artifacts).
- Entity keys map 1:1 to existing `st.*` / district slugs; no new ids.

## 3. The copy evidence bar (E-5/G12) — enforced, tested

Per the amended E-5, the exporter enforces:

| Tier | Where it may appear | Rule |
|---|---|---|
| `corroborated` (canonical families, post-B-10) | card preview + guide narrative | allowed |
| `proposed` | guide narrative only, **with attribution** ("one source: …") | preview-forbidden |
| `conflicted` | **never in copy** — evidence disclosure only | enforced |
| `researcher_inference` | **never in copy** | enforced |
| Thai-sourced claims outside the A-6 human pass | **excluded from copy** until signed | enforced |

**Human-sign-off key (v2.3 amendment):** a bundle whose `review.reviewer`
starts with `agent-review:` is **not copy-eligible** — the exporter emits
identity/score only for it until a human signatory records approval. This
makes the current 46 bundles data-visible but *not copy-shipping* until A-1
signs. **Test case in CI:** a fixture bundle per violating class must fail
the exporter.

## 4. Guide structure (handoff section order)

Rendered guide follows the handoff order: identity/scope → distinctive
character → strengths and trade-offs → conditional fit / time / subareas →
deeper facts and sources → optional gallery (empty until WS-G). Voice/length
normalization (E-8/G23) happens **on structured fields at export time**:
preview ≤ 220 chars guide-capped, per-section caps, event dates rendered with
their dates (never unanchored "recently"), rhythm claims carry observed-period
labels. No semantic rewrites — caps truncate at sentence boundaries with an
ellipsis + the full text remains in the on-demand chunk.

## 5. Tier-C card (DEC-8 default: adopted)

137 guide-less entities render an explicit **data-only card** (score + facts
+ a one-line "editorial guide pending" label). The exporter **never
synthesizes guide-like prose** for unresearched units (E-6/WS-H #3). A unit
test asserts no tier-C chunk contains narrative fields.

## 6. Disclosures (E-3)

Score-context disclosures live **one tap from the score**: green 1 km buffer
basis (DEC-6), transport mechanism (buses + piers; nearest-stop rule), rent
label semantics (blend/override/median visible in ComparePanel — B-5's labels
stay), plus the corpus-skew line (expat/tourist source skew, score-correlated
selection, single-season observations — C-ep4).

## 7. Attribution & provenance

- Every copy sentence carries its claim IDs; the evidence drawer resolves
  them via the **canonical source registry** (`kit/registry/source-attributions.json`,
  B-11) so merged citation views show one attribution per URL.
- Untrusted-text rule: all research text renders as **plain text only** (no
  HTML/markdown interpretation); the G20 sweep result is recorded per bundle
  at export time and re-checked.

## 8. Existing short-copy reconciliation

`app/src/data/area-guide-copy.json` holds exactly six hand-written keys (the
pilot set). **Never silently overwritten**: the exporter detects collisions
and emits them to a migration manifest (`editorial-migration.json`) for a
reviewed, versioned replacement — editorial keys win only after that review
lands.

## 9. Rollback & flags

- The whole slice ships behind a **feature flag** (`bangkokEditorial`);
  rollback = flag off (no data removal needed; index/chunks are additive files).
- The exporter is deterministic (stable key order, recorded input digests) so
  re-runs are diffable.

## 10. Acceptance (E-2 gates)

App checks green (lint, toolchain tests, TS, production build, e2e) · bundle
delta within budget · evidence-bar + tier-C + sign-off-key tests present ·
disclosures live · migration manifest reviewed · flag documented. **Not
started until A-1 signs.**
